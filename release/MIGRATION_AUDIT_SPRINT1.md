## STEP 6 — Deployment Plan

### Staging

1. `git pull origin main`
2. `python manage.py makemigrations --check --dry-run` → confirm `No changes detected`
3. `python manage.py migrate`
4. Run smoke tests:
   - `python manage.py test operations authapp notifications payments security`
   - Verify `/operations/business/hub/` returns HTTP 200
5. Deploy admin frontend build if not already present.

### Production

1. Ensure encrypted backup exists (`scripts/backup-encrypted.sh`).
2. `git pull origin main`
3. `docker compose -p yala build django`
4. `docker compose -p yala up -d django django-replica django-replica-2`
5. `docker compose -p yala exec django python manage.py migrate --plan` (review only two safe `AlterField` operations)
6. `docker compose -p yala exec django python manage.py migrate`
7. `curl -fsS https://api.yalataxi.live/health/`
8. Reload nginx if static/admin bundle changed: `docker exec yala-nginx-1 nginx -s reload`

### Rollback Plan

- The two generated migrations are irreversible only if data were lost, but no data is changed.
- If needed, revert via Django: `python manage.py migrate notifications 0005` and `python manage.py migrate security 0002`.
- For the `authapp`/`payments` model fixes (constraint alignment), revert the model code changes and re-run `makemigrations` if a rollback is required.
- Database-level rollback: restore from the pre-deploy encrypted backup.
