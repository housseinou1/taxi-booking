# Requirements Document

## Introduction

The Yala Referral Program enables both Riders and Drivers to grow the platform organically through word-of-mouth. Riders can share referral codes with friends to earn ride credits, while existing Drivers can refer new drivers and receive bonuses after the referred driver completes a configurable number of rides. An Admin Dashboard provides referral analytics, reward management, and fraud detection capabilities. All referral reward amounts and thresholds are configurable by administrators.

## Glossary

- **Referral_System**: The backend Django application responsible for managing referral codes, tracking referral signups, awarding credits/bonuses, and detecting fraud.
- **Rider_Referral_Engine**: The component that handles rider-to-rider referral code generation, sharing, validation, and credit issuance.
- **Driver_Referral_Engine**: The component that handles driver-to-driver referral tracking, ride-count threshold monitoring, and bonus issuance.
- **Referral_Admin_Dashboard**: The admin interface providing referral analytics, reward configuration, and fraud detection tools.
- **Referral_Code**: A unique alphanumeric string assigned to or generated by a user for sharing with potential new users.
- **Referrer**: An existing user (Rider or Driver) who shares a referral code to invite new users.
- **Referee**: A new user who signs up using a referral code.
- **Ride_Credit**: A monetary credit applied to a Rider's account that can be used toward future ride fares.
- **Driver_Bonus**: A monetary reward paid to a referring Driver after the referred Driver meets the qualifying ride threshold.
- **Reward_Configuration**: An admin-managed set of parameters defining referral reward amounts, thresholds, expiration periods, and limits.
- **Fraud_Detection_Engine**: The component that analyzes referral activity to identify and flag suspicious patterns.

## Requirements

### Requirement 1: Rider Referral Code Generation

**User Story:** As a Rider, I want to have a unique referral code, so that I can share it with friends to invite them to the platform.

#### Acceptance Criteria

1. WHEN a Rider account is created, THE Rider_Referral_Engine SHALL generate a unique referral code consisting of exactly 8 characters from the set [A-Z, 0-9] for that Rider.
2. WHEN a Rider requests a referral code and one already exists, THE Rider_Referral_Engine SHALL return the existing referral code.
3. THE Rider_Referral_Engine SHALL store and compare referral codes as case-insensitive values, treating "AbC123XY" and "abc123xy" as identical.
4. WHEN a referral code generation results in a duplicate, THE Rider_Referral_Engine SHALL retry generation up to a maximum of 5 attempts until a unique code is produced.
5. IF referral code generation fails to produce a unique code after 5 attempts, THEN THE Rider_Referral_Engine SHALL abort code generation, not assign a referral code to the Rider, and return an error indicating that code generation failed.

### Requirement 2: Rider Referral Code Sharing

**User Story:** As a Rider, I want to share my referral code through various channels, so that I can easily invite friends to use Yala.

#### Acceptance Criteria

1. WHEN a Rider requests to share a referral code, THE Rider_Referral_Engine SHALL return the referral code as a plain-text string and a pre-formatted shareable message containing the referral code and a signup link.
2. THE Rider_Referral_Engine SHALL provide an API endpoint that returns the authenticated Rider's referral code, total number of successful referrals, and total credits earned.
3. WHEN a Rider views referral statistics, THE Rider_Referral_Engine SHALL display the total number of successful referrals, where a successful referral is defined as a Referee who has completed their first ride, and the total Ride_Credits earned expressed as a monetary amount.
4. IF a Rider requests to share a referral code and no referral code exists for that account, THEN THE Rider_Referral_Engine SHALL generate a referral code as defined in Requirement 1 before returning it.
5. IF an unauthenticated or invalid request is made to the referral code sharing endpoint, THEN THE Rider_Referral_Engine SHALL reject the request with an error indicating authentication is required.

### Requirement 3: Rider Referral Signup Validation

**User Story:** As a new Rider, I want to apply a referral code during signup, so that both my referrer and I receive benefits.

#### Acceptance Criteria

1. WHEN a new Rider provides a referral code during registration, THE Rider_Referral_Engine SHALL validate that the code exists and belongs to an active Rider account within 2 seconds of submission.
2. IF a provided referral code does not exist, THEN THE Rider_Referral_Engine SHALL reject the registration referral field and return an error message indicating the code is not recognized.
3. IF a new Rider attempts to use a referral code belonging to a suspended or inactive account, THEN THE Rider_Referral_Engine SHALL reject the code with an error message indicating the referrer account is not eligible.
4. WHEN a new Rider completes registration with a valid referral code, THE Rider_Referral_Engine SHALL record the association between the Referee and the Referrer.
5. THE Rider_Referral_Engine SHALL accept at most one referral code per account creation and discard any additional codes submitted in the same registration request.
6. IF a new Rider provides their own referral code during registration, THEN THE Rider_Referral_Engine SHALL reject the code with an error message indicating self-referral is not permitted.
7. IF a provided referral code does not match the format of exactly 8 alphanumeric characters, THEN THE Rider_Referral_Engine SHALL reject the code with an error message indicating the code format is invalid without querying the database.

### Requirement 4: Rider Referral Credit Issuance

**User Story:** As a Rider Referrer, I want to receive ride credit when my referred friend signs up and completes a ride, so that I am rewarded for growing the platform.

#### Acceptance Criteria

1. WHEN a Referee completes their first ride, THE Rider_Referral_Engine SHALL issue a Ride_Credit to the Referrer's account in the amount specified by the active Reward_Configuration.
2. WHEN a Referee completes their first ride, THE Rider_Referral_Engine SHALL issue a Ride_Credit to the Referee's account in the amount specified by the active Reward_Configuration.
3. WHEN a Rider's ride fare is calculated and the Rider has an available Ride_Credit balance, THE Rider_Referral_Engine SHALL apply the Ride_Credit as a discount up to the total fare amount, reducing the Rider's payment to no less than zero.
4. IF the Referrer's account has been suspended at the time of credit issuance, THEN THE Rider_Referral_Engine SHALL withhold the credit and log the event for admin review.
5. WHEN a referral credit is issued, THE Rider_Referral_Engine SHALL send a notification to the Referrer indicating the credit amount and reason.
6. WHEN a referral credit is issued to a Referee, THE Rider_Referral_Engine SHALL send a notification to the Referee indicating the credit amount and reason.
7. IF the Referrer has already earned the maximum number of referral credits allowed within the configured time period, THEN THE Rider_Referral_Engine SHALL withhold the credit and notify the Referrer that the referral cap has been reached.
8. IF the Referee's first ride is cancelled or reversed after credit issuance, THEN THE Rider_Referral_Engine SHALL revoke the Ride_Credits issued to both the Referrer and the Referee for that referral.

### Requirement 5: Driver Referral Code Generation

**User Story:** As a Driver, I want to have a unique referral code, so that I can refer new drivers to the platform.

#### Acceptance Criteria

1. WHEN a Driver account reaches approved status, THE Driver_Referral_Engine SHALL generate a unique referral code consisting of exactly 8 alphanumeric characters (uppercase letters A-Z and digits 0-9) for that Driver.
2. WHEN a Driver requests a referral code and one already exists, THE Driver_Referral_Engine SHALL return the existing referral code.
3. THE Driver_Referral_Engine SHALL store and compare driver referral codes as case-insensitive values.
4. IF the Driver_Referral_Engine generates a code that already exists in the system, THEN THE Driver_Referral_Engine SHALL retry code generation up to 5 times before returning an error indicating that code generation failed.

### Requirement 6: Driver Referral Tracking

**User Story:** As an existing Driver, I want to refer new drivers and track their progress, so that I know when I will receive my bonus.

#### Acceptance Criteria

1. WHEN a new Driver signs up with a valid driver referral code, THE Driver_Referral_Engine SHALL record the referral relationship between the Referrer and Referee, including the referral date and the ride threshold from the active Reward_Configuration at the time of signup.
2. THE Driver_Referral_Engine SHALL accept only one referral code per new Driver account registration.
3. WHILE a referred Driver has not completed the number of rides specified in their associated Reward_Configuration threshold, THE Driver_Referral_Engine SHALL increment the referred Driver's completed ride count each time a ride reaches completed status.
4. WHEN a Referrer requests referral status, THE Driver_Referral_Engine SHALL return the list of referred Drivers, each with the number of completed rides, the required ride threshold, and the bonus status as one of: pending, completed, or expired.
5. IF a referred Driver's account is marked as suspended by an administrator or has had no completed rides for 90 consecutive days before reaching the ride threshold, THEN THE Driver_Referral_Engine SHALL mark the referral as expired and send a notification to the Referrer indicating the referral expiration and reason.
6. IF a new Driver provides a referral code that does not exist or belongs to a suspended or inactive Driver account, THEN THE Driver_Referral_Engine SHALL reject the code and return an error message indicating the referral code is invalid.

### Requirement 7: Driver Referral Bonus Issuance

**User Story:** As a Driver Referrer, I want to receive a bonus when my referred driver completes the required rides, so that I am rewarded for bringing quality drivers to the platform.

#### Acceptance Criteria

1. WHEN a referred Driver completes the minimum number of rides specified in the active Reward_Configuration, THE Driver_Referral_Engine SHALL issue exactly one Driver_Bonus to the Referrer's account in the amount defined by the active Reward_Configuration, and SHALL reject any subsequent bonus issuance attempts for the same referral relationship.
2. WHEN a Driver_Bonus is issued, THE Driver_Referral_Engine SHALL send a notification to the Referrer within 60 seconds containing the bonus amount and the referred Driver's name.
3. THE Driver_Referral_Engine SHALL record each bonus payment with the Referrer identifier, Referee identifier, bonus amount, issuance timestamp, and referral relationship identifier.
4. IF the Referrer's account has been suspended at the time of bonus issuance, THEN THE Driver_Referral_Engine SHALL withhold the bonus, log the event for admin review, and retain the withheld bonus in a pending state linked to the referral relationship.
5. IF the Referrer has already reached the maximum number of referral bonuses allowed within the configured time period defined in the Reward_Configuration, THEN THE Driver_Referral_Engine SHALL withhold the bonus and notify the Referrer that their referral bonus cap has been reached.
6. WHEN a Referrer's account is reinstated from suspended status and has withheld bonuses in pending state, THE Driver_Referral_Engine SHALL issue all pending Driver_Bonuses to the Referrer's account and send a notification for each issued bonus.

### Requirement 8: Configurable Referral Rewards

**User Story:** As an Admin, I want to configure referral reward parameters, so that I can adjust the program based on business needs and market conditions.

#### Acceptance Criteria

1. THE Referral_Admin_Dashboard SHALL allow administrators to configure the Rider referral credit amount for Referrers as a monetary value between 0.01 and 10,000.00 in the platform's base currency.
2. THE Referral_Admin_Dashboard SHALL allow administrators to configure the Rider referral credit amount for Referees as a monetary value between 0.01 and 10,000.00 in the platform's base currency.
3. THE Referral_Admin_Dashboard SHALL allow administrators to configure the Driver referral bonus amount as a monetary value between 0.01 and 50,000.00 in the platform's base currency.
4. THE Referral_Admin_Dashboard SHALL allow administrators to configure the minimum number of rides a referred Driver must complete before the bonus is issued as an integer between 1 and 500.
5. THE Referral_Admin_Dashboard SHALL allow administrators to configure a maximum number of referral credits a single Rider can earn within a specified time period, where the limit is an integer between 1 and 1,000 and the time period is specified in days between 1 and 365.
6. THE Referral_Admin_Dashboard SHALL allow administrators to configure a maximum number of referral bonuses a single Driver can earn within a specified time period, where the limit is an integer between 1 and 1,000 and the time period is specified in days between 1 and 365.
7. WHEN an administrator updates a Reward_Configuration, THE Referral_System SHALL apply the new configuration to all future referral events without affecting already-issued rewards.
8. THE Referral_Admin_Dashboard SHALL allow administrators to configure an expiration period for referral credits as a number of days between 1 and 730.
9. IF an administrator submits a Reward_Configuration value outside the allowed range, THEN THE Referral_Admin_Dashboard SHALL reject the submission, display an error message indicating the invalid field and its allowed range, and retain the previously saved configuration.
10. WHEN an administrator saves a valid Reward_Configuration, THE Referral_Admin_Dashboard SHALL display a confirmation indicating the configuration was updated successfully and the timestamp of the change.

### Requirement 9: Referral Analytics Dashboard

**User Story:** As an Admin, I want to view referral program analytics, so that I can monitor program performance and make data-driven decisions.

#### Acceptance Criteria

1. THE Referral_Admin_Dashboard SHALL display the total number of referral signups for Riders and Drivers separately, where a referral signup is defined as a new account created using a valid referral code.
2. THE Referral_Admin_Dashboard SHALL display the total amount of referral credits and bonuses issued within the selected date range, defaulting to the last 30 days when no date range filter is applied.
3. THE Referral_Admin_Dashboard SHALL display the conversion rate as a percentage calculated by dividing the number of Referees who completed their first ride by the total number of referral signups, displayed to one decimal place.
4. THE Referral_Admin_Dashboard SHALL display the top 10 Referrers ranked by number of successful referrals, where a successful referral is one in which the Referee completed their first ride.
5. THE Referral_Admin_Dashboard SHALL display referral activity trends showing the number of new referral signups and the number of completed first rides over time, in daily, weekly, and monthly aggregations.
6. WHEN an administrator selects a date range filter, THE Referral_Admin_Dashboard SHALL update all analytics metrics to reflect the selected period within 5 seconds.
7. IF the selected date range contains no referral data, THEN THE Referral_Admin_Dashboard SHALL display a message indicating no referral activity exists for the selected period and show all metric values as zero.

### Requirement 10: Referral Fraud Detection

**User Story:** As an Admin, I want the system to detect and flag suspicious referral activity, so that the program is protected from abuse.

#### Acceptance Criteria

1. WHEN 3 or more referral signups originate from the same device identifier within a 24-hour period, THE Fraud_Detection_Engine SHALL flag those referrals as suspicious.
2. WHEN a single Referrer accumulates referral credits exceeding the configured daily threshold (default: 10 referral credits per 24-hour period), THE Fraud_Detection_Engine SHALL flag the Referrer's account for review.
3. WHEN a referred account completes a qualifying ride and records no subsequent login or ride activity within 48 hours after that ride, THE Fraud_Detection_Engine SHALL flag the referral as potentially fraudulent.
4. WHEN a referral is flagged as suspicious, THE Fraud_Detection_Engine SHALL withhold pending rewards until an administrator approves or rejects the referral, and IF no administrator action is taken within 30 calendar days, THEN THE Fraud_Detection_Engine SHALL escalate the flagged referral to a senior administrator.
5. THE Referral_Admin_Dashboard SHALL display a paginated list of flagged referrals showing the referrer identifier, referred account identifier, flag reason, and flag timestamp, and allow administrators to approve or reject each flagged referral.
6. WHEN an administrator rejects a flagged referral, THE Fraud_Detection_Engine SHALL revoke any pending credits or bonuses associated with that referral, and IF rewards have already been disbursed, THEN THE Fraud_Detection_Engine SHALL deduct the equivalent amount from the Referrer's available balance.
7. WHEN an administrator approves a flagged referral, THE Fraud_Detection_Engine SHALL release the withheld rewards to the appropriate accounts within 60 seconds of approval.
8. WHEN one or more referrals are newly flagged, THE Fraud_Detection_Engine SHALL send a notification to administrators with access to the Referral_Admin_Dashboard indicating the number of referrals awaiting review.

### Requirement 11: Referral Credit Expiration

**User Story:** As a platform operator, I want referral credits to expire after a configurable period, so that unused credits do not accumulate indefinitely as liabilities.

#### Acceptance Criteria

1. WHEN a Ride_Credit remains unused or partially unused beyond the expiration period defined in the Reward_Configuration calculated from the credit's issuance date, THE Rider_Referral_Engine SHALL mark the credit as expired and set its remaining value to zero.
2. WHEN a Ride_Credit reaches 7 days before its expiration date, THE Rider_Referral_Engine SHALL send a single reminder notification to the Rider indicating the credit amount and expiration date.
3. IF a Ride_Credit has expired, THEN THE Rider_Referral_Engine SHALL exclude that credit from the Rider's available balance and prevent it from being applied to future rides.
4. IF a Ride_Credit is currently applied to a ride that is in progress or scheduled at the time of expiration, THEN THE Rider_Referral_Engine SHALL honor the credit for that ride and expire only the remaining unused portion after the ride is completed.
